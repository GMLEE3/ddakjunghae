# 프로젝트 개발 규칙 (Development Rules)

> 딱정해 프로젝트의 모든 개발 작업에 적용되는 규칙

---

## 1. 작업 시작 전 점검

- [ ] `docs/PRD.md` 읽고 현재 진행 상황 확인
- [ ] `docs/MVP.md` 읽고 MVP 범위 내 작업인지 확인
- [ ] `docs/development-plan.md` 에서 관련 개발 계획 확인

---

## 2. 문서 연동 규칙

| 시점 | 작업 |
|------|------|
| 작업 시작 전 | PRD/MVP/개발계획서 확인 |
| 작업 완료 후 | 해당 문서에 진행 상황 반영 |
| 새 기능 추가 시 | PRD에 기능 추가, 개발계획서 업데이트 |

---

## 3. 테스트 규칙

모든 개발 사항은 다음 점검을 통과해야 함:

### 백엔드 테스트
- API 엔드포인트 응답 확인
- 에러 핸들링 테스트
- 목 데이터 폴백 동작 확인

### 프론트엔드 테스트
- UI 렌더링 확인
- 사용자 인터랙션 테스트
- 반응형 레이아웃 확인

### 교차 점검
- 백엔드 API → 프론트엔드 화면 출력 연결 확인
- 에러 상황에서 적절한 UI 피드백 표시 확인

---

## 4. 언어 규칙

| 항목 | 언어 |
|------|------|
| LLM ↔ 사용자 소통 | 한국어 |
| 파일명 | 영어 (예: `RecommendCard.tsx`) |
| 코드 주석 | 한국어 |
| 변수/함수명 | 영어 (camelCase) |
| 커밋 메시지 | 한국어 또는 영어 |

---

## 5. 의견 제안 규칙

새로운 의견을 낼 때:
- ✅ 프로젝트 비즈니스 목표와 연결된 제안
- ✅ MVP 핵심 기능과 밀접하게 연결된 내용
- ❌ 기술적으로 멋지지만 사용자 가치와 무관한 기능
- ❌ MVP 범위를 벗어나는 복잡한 기능

---

## 6. 코드 품질 규칙

### 파일 크기 제한
- **500줄 초과 시 파일 분리 필수**
- 예: `utils.ts` → `utils/formatting.ts`, `utils/validation.ts`

### 파일 구조
```
src/
├── app/            # 페이지 및 API 라우트
├── components/     # UI 컴포넌트
│   └── [기능]/    # 기능별 폴더
├── hooks/          # 커스텀 훅
├── lib/            # 유틸리티 함수
└── types/          # 타입 정의
```
